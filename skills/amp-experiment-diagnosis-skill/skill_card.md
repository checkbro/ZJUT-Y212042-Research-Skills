# Skill Card: AMP Experiment Diagnosis Skill

## 1. Skill 基本信息

- Skill 名称：`amp-experiment-diagnosis-skill`
- 中文名称：AMP 运动控制实验诊断 Skill
- 研究场景：基于 AMP / 强化学习的人形或小型双足机器人运动控制实验诊断
- 适用框架：AMP_mjlab、RSL-RL、Isaac/Genesis/MuJoCo 类机器人训练框架中的速度跟踪与风格模仿实验

## 2. 解决的研究问题

这个 Skill 用来分析 AMP 机器人训练中“看起来学到了步态风格，但某些速度指令不听话”的问题。例如：

- 纯前向速度 `(vx>0, vy=0, wz=0)` 下机器人不起步，但混入侧向速度后可以走起来。
- 原地旋转需要 `|wz|` 给到很高才会顺滑转动。
- 横移、旋转、前向行走之间存在互相遗忘。
- 新定向轨迹加入后，判别器数据、任务奖励、命令采样之间出现冲突。
- G1 动作重定向到 Dittle 时出现手臂反关节、脚底高度不对、左右方向覆盖不平衡等问题。

## 3. 输入材料

- 用户现象描述：固定速度指令、观察结果、期望结果、checkpoint。
- 训练日志：reward、velocity error、episode length、AMP loss、自定义 metric。
- 环境配置：速度奖励权重/std、命令采样范围、reset、heading/gait、foot slip、力矩限制。
- RL 配置：`amp_reward_coef`、`amp_task_reward_lerp`、epoch、mini-batch、num steps、学习率、resume checkpoint。
- 动作数据清单：轨迹数量、方向覆盖、左右配对、重定向方法、是否误读 backup 文件夹。
- 播放测试结果：不同固定命令下的实际速度、是否需要推一把、是否需要输入偏置。

## 4. 输出结果

Skill 输出一份结构化诊断报告，包含：

- 核心结论摘要
- 证据清单
- 问题-证据-置信度-人工确认-下一步实验表格
- 当前配置快照
- 动作数据覆盖审计
- 固定命令 playback 测试矩阵
- 最小化下一轮实验设计
- 仍然缺失的证据与不确定性

## 5. 和普通 ChatGPT 问答的区别

普通问答容易给出“提高速度奖励”“降低 AMP 权重”这类泛化建议，但不一定说明证据来源。这个 Skill 强制把每个结论绑定到日志、配置、动作数据或 playback 现象上，并区分事实与假设。

它不是简单总结，而是围绕一个真实实验闭环工作：定位问题、核对配置、审计动作数据、解释失败模式、设计下一版训练。

## 6. 可靠性与验证方式

- 所有高置信度结论必须有明确证据，例如日志指标、配置数值、文件路径或固定命令测试结果。
- 对判别器方向覆盖、AMP/task 冲突等机制性解释必须标为“假设”，除非已有对照实验支持。
- 每次建议只改变一个主变量，便于复现实验。
- 输出中必须保留“需要人工确认”的项，例如轨迹视觉质量、脚步滑动、是否真正原地旋转。

## 7. 示例任务

输入：Dittle AMP 训练中，`model_4000.pt` 在 `(0.8,0,0)` 下不起步，`(0.8,0.2,0)` 可以起步，原地转向必须 `|wz|>1.4` 才顺滑。

输出：Skill 会检查速度奖励、AMP/task 混合、动作数据方向覆盖、重定向质量、命令采样和 playback 矩阵，给出一份证据表，并建议下一轮训练或控制输入策略。

## 8. 局限性

- Skill 不能替代真实仿真 playback。视觉上的接触、滑步、关节异常仍需要人工检查。
- 如果没有实际速度测量，关于“跟踪失败”的判断只能基于现象描述和训练日志，置信度会降低。
- 如果动作数据来自外部数据集，Skill 只能检查文件和统计信息，不能保证动作语义完全正确。
